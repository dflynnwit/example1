# Scrum Framework Guide

## Overview
Scrum is an Agile framework for developing, delivering, and sustaining complex products. This document outlines the Scrum practices implemented in our coursework.

## Scrum Roles

### Product Owner
- Defines product vision and roadmap
- Manages and prioritizes product backlog
- Ensures team delivers value to stakeholders
- Makes decisions on scope and release dates

### Scrum Master
- Facilitates Scrum events
- Removes impediments blocking the team
- Coaches team on Agile practices
- Shields team from external interruptions

### Development Team
- Cross-functional and self-organizing
- Typically 3-9 members
- Collectively responsible for deliverables
- Participates in all Scrum ceremonies

## Scrum Events

### Sprint
- Time-boxed iteration (1-4 weeks)
- Creates a potentially shippable product increment
- Fixed duration throughout the project

### Sprint Planning
- **Duration**: 2-4 hours for a 2-week sprint
- **Participants**: Entire Scrum team
- **Outcomes**:
  - Sprint Goal defined
  - Sprint Backlog created
  - Team commits to deliverables

### Daily Scrum (Standup)
- **Duration**: 15 minutes
- **Time**: Same time/place daily
- **Format**:
  - What did I do yesterday?
  - What will I do today?
  - Are there any impediments?

### Sprint Review
- **Duration**: 1-2 hours for a 2-week sprint
- **Participants**: Scrum team + stakeholders
- **Activities**:
  - Demonstrate completed work
  - Gather feedback
  - Update product backlog

### Sprint Retrospective
- **Duration**: 1-1.5 hours for a 2-week sprint
- **Participants**: Scrum team only
- **Focus**:
  - What went well?
  - What could be improved?
  - Action items for next sprint

## Scrum Artifacts

### Product Backlog
- Ordered list of features, enhancements, fixes
- Prioritized by Product Owner
- Living document, continuously refined
- Items include user stories, technical tasks

### Sprint Backlog
- Selected Product Backlog items for the sprint
- Plan for delivering the Sprint Goal
- Owned and managed by Development Team
- Updated daily

### Increment
- Sum of all completed Product Backlog items
- Must meet Definition of Done
- Must be in usable condition
- Released at Product Owner's discretion

## Definition of Done (DoD)
A shared understanding of what "done" means:
- Code written and peer-reviewed
- Unit tests written and passing
- Integration tests passing
- Documentation updated
- Code merged to main branch
- Acceptance criteria met
- No known defects

## Key Metrics

### Velocity
- Amount of work completed per sprint
- Measured in story points
- Used for sprint planning and forecasting

### Burndown Chart
- Visual representation of work remaining
- Updated daily
- Helps track sprint progress

### Burnup Chart
- Shows work completed over time
- Tracks scope changes
- Useful for release planning

## Best Practices
1. **Keep sprints consistent** - Same duration throughout project
2. **Don't skip ceremonies** - Each has a specific purpose
3. **Maintain sustainable pace** - Avoid overtime and burnout
4. **Embrace change** - Adapt based on feedback and learnings
5. **Focus on value** - Prioritize features that deliver most value
6. **Continuous improvement** - Apply retrospective learnings

## Common Challenges and Solutions

### Challenge: Scope Creep
**Solution**: Protect the sprint scope; new items go to product backlog

### Challenge: Unfinished Work
**Solution**: Review sprint commitment and estimation accuracy

### Challenge: Lack of Stakeholder Engagement
**Solution**: Demonstrate value early and often; invite to sprint reviews

### Challenge: Team Dependencies
**Solution**: Identify dependencies early; work to remove them
